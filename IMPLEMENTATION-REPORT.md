# Отчёт разработчика

## Блокеры запуска

- окончательный домен; российский хостер, адрес, роль и условия поручения;
- адреса основной базы, файлов и резервных копий в РФ;
- регистрационные сведения из выписки ЕГРИП;
- утверждённые даты и версии документов, сроки 90/30/180 дней;
- факт уведомления РКН;
- ID и проверенная настройка Метрики;
- административные реквизиты, Telegram-бот, оценка и уведомление о трансграничной передаче, утверждённые гарантийные условия.

## Режим и развёртывание

Сбор заявок, Метрика и полная передача заявок в Telegram выключены по умолчанию. Фото хранятся вне web-root и преобразуются в WebP без исходных метаданных. При отдельно разрешённом полном режиме Telegram получает имя, телефон и фото с `protect_content`; доставка выполняется через очередь с повторными попытками. Это не отменяет облачное хранение Telegram и юридические действия до включения.

1. Заполнить `.env.example` подтверждёнными значениями в защищённой конфигурации сервера.
2. Получить хеш: `node -e "import('bcryptjs').then(b=>b.hash(process.argv[1],12).then(console.log))" 'пароль'`.
3. Выполнить `npm ci`, `npm run build`, `npm run start` под непривилегированным пользователем за HTTPS reverse proxy в РФ.
4. Закрыть доступ к `DATA_DIR`; бэкапы хранить в РФ до 30 дней. Не журналировать тела запросов и персональные поля.

География инфраструктуры, договор, резервное восстановление, РКН, Telegram и Метрика проверяются после предоставления реальной инфраструктуры. Документы остаются черновиками до утверждения владельцем.
