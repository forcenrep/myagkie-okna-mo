# Настройка Telegram-бота на VPS

## Что реализовано

- без фото: `sendMessage` с именем, телефоном и временем заявки;
- с фото: `sendPhoto`, те же данные находятся в подписи;
- `protect_content=true` ограничивает пересылку и сохранение средствами клиента Telegram;
- токен и ID чата существуют только в переменных окружения сервера;
- после сохранения заявки создаётся запись доставки; временные ошибки повторяются с увеличивающейся задержкой, максимум 10 попыток;
- сбой Telegram не удаляет заявку из российской базы;
- статус доставки виден в административной панели.

## Получение реквизитов

1. Создать бота через официальный `@BotFather` и получить токен.
2. Получатель должен первым открыть диалог с ботом и нажать **Start**.
3. Получить числовой `chat_id` через `getUpdates` либо служебным скриптом. Не использовать username как средство контроля доступа.
4. Хранить токен только на VPS в закрытом `.env`/секретах systemd или Docker. Никогда не отправлять его в браузер и не коммитить.

## Переменные VPS

```dotenv
TELEGRAM_FULL_LEADS_ENABLED=false
TELEGRAM_BOT_TOKEN=123456:секрет
TELEGRAM_CHAT_ID=123456789
```

Сначала оставить флаг `false`. После теста российского хранилища, утверждения новой версии согласия и выполнения применимых требований к трансграничной передаче изменить его на `true` и перезапустить процесс.

`TELEGRAM_API_BASE` в production не задаётся: по умолчанию используется `https://api.telegram.org`.

## Проверка перед включением

1. Убедиться, что сайт сначала сохраняет заявку и фото в базе/хранилище на территории РФ.
2. Подать фиктивную заявку без реальных персональных данных.
3. Проверить единое сообщение без фото и единое сообщение с фото и подписью.
4. Временно заблокировать исходящий доступ к Telegram, убедиться, что заявка сохраняется, а доставка получает статус `pending`, затем восстановить сеть и дождаться `sent`.
5. Проверить, что чат закрытый и доступ есть только у назначенного получателя.
6. Утвердить регламент удаления сообщений из Telegram. Удаление записи с VPS не гарантирует удаления уже отправленного облачного сообщения.

## Сетевая доступность

VPS должен разрешать исходящие HTTPS-запросы на `api.telegram.org:443` и корректно разрешать DNS. Входящий webhook не нужен: сайт сам вызывает Bot API после сохранения заявки.
